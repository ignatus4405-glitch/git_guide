# Формат контента курса

Всё содержимое курса — обычный markdown с front matter. Сайт собирается из этих файлов
`build.py`, поэтому соблюдение формата проверяется автоматически (`tools/validate.py --strict`).

## Где что лежит

```text
content/
├── modules.yml          # список модулей: id, dir, title, description, icon, level
├── pages/               # отдельные страницы (index, karta-kursa, shpargalka, slovar, …)
└── <dir>/               # каталог модуля
    ├── index.md         # обзор модуля (необязателен)
    └── NN-slug.md       # уроки: NN — порядок в модуле
```

Имя файла урока задаёт его `slug`: `04-otmena-i-rebase.md` → ссылка `lesson:otmena-i-rebase`.

## Front matter урока

```yaml
---
title: "rebase, отмена и спасение работы"     # обязателен, попадает в <h1> и навигацию
summary: "Осознанный выбор между merge и rebase…"  # обязателен, 40–260 символов
order: 4                                     # обязателен, порядок в модуле
updated: 2026-10-15                          # обязателен, формат YYYY-MM-DD
tags: [git, rebase, reset]                   # обязательны, используются в навигации и поиске
goals:                                       # минимум две измеримые цели
  - Осознанно выбирать между merge и rebase
  - Использовать интерактивный rebase для чистки коммитов
---
```

Front matter страницы (`content/pages/`) короче:

```yaml
---
title: "Шпаргалка по Git и GitHub"
summary: "Все команды курса в одном месте."
order: 2
updated: 2026-10-15
icon: "🧾"           # эмодзи для сайдбара
nav_title: "Шпаргалка команд"   # необязательно: короткое имя в навигации
nav: true            # false — не показывать в сайдбаре (например, для главной)
---
```

## Требования к уроку

Проверяются валидатором:

- объём **не меньше 400 слов** (ошибка — меньше 250), поэтому пишите развёрнуто, но по делу;
- минимум **один блок кода** и **один вопрос самопроверки** `::: quiz`;
- минимум две цели в `goals`;
- ни одного `TODO`, `FIXME`, `TBD`, `Lorem ipsum` и слова «заглушка»;
- сбалансированные блоки: каждая `:::` закрыта строкой `:::` без текста, каждый ``` ``` закрыт.

## Разметка

### Заголовки

`##` — раздел (попадает в оглавление справа), `###` и `####` — подразделы.
Не используйте `#` внутри урока: заголовок страницы ставится автоматически.

### Блоки кода

````text
```bash title="Первый коммит"
git add README.md
git commit -m "docs: добавить описание"
```
````

Поддерживаемые языки (`bash`, `yaml`, `python`, `json`, `ini`, `diff`, `text`, `powershell`, `html`…)
и алиасы перечислены в `tools/highlight.py`. Блок без языка допустим, но даёт предупреждение.

### Врезки

```text
::: tip Заголовок врезки
Текст. Внутри работает любой markdown, включая списки, таблицы и код.
:::
```

Типы: `note`, `info`, `tip`, `success`, `warning`, `danger`, `exercise`, `goal`, `details`,
`terminal`, `history`, `columns`, `quiz`. Тип `details` рендерится сворачиваемым блоком;
`columns` делит содержимое на две колонки по строкам `---`.

### Вопросы самопроверки

```text
::: quiz Что произойдёт после git fetch?
- ( ) Файлы обновятся до состояния origin/main
- (x) Обновятся только удалённые ссылки, файлы не тронутся
- ( ) Git создаст merge-коммит

Пояснение: почему верный вариант верный и что произойдёт при других.
:::
```

Правила: ровно один вариант с `(x)`, минимум два варианта, после вариантов — абзац-пояснение.

### Схемы и картинки

```text
![Схема: три дерева Git](assets/img/diagrams/three-trees.svg "Подпись под схемой")
```

Имя файла должно быть в реестре `DIAGRAMS` (`tools/gen_diagrams.py`) — иначе валидатор
сообщит, что схема не генерируется. Внешние картинки (`https://…`) разрешены, но нежелательны:
курс должен работать офлайн.

### Таблицы, списки, сноски-выделения

Поддерживаются таблицы GFM с выравниванием (`| --- | ---: |`), вложенные списки,
чек-листы (`- [x]`), цитаты (`>`), `**жирный**`, `*курсив*`, `` `код` ``, `~~зачёркнутый~~`,
`==выделенный==`. «Сырой» HTML разрешён для тегов из белого списка
(`<kbd>`, `<details>`, `<div>`…); скрипты, `onclick` и `javascript:` удаляются автоматически.

### Токены сборки

| Токен | Что подставляет |
| --- | --- |
| `[[STATS]]` | блок статистики курса (модули, уроки, вопросы, минуты) |
| `[[MODULE_MAP]]` | карта всех модулей с уроками и временем чтения |
| `[[MODULE_CARDS]]` | сетка карточек модулей (используется на главной) |
| `[[LESSON_COUNT]]` | число уроков |

## Ссылки между материалами

| Схема | Пример | Куда ведёт |
| --- | --- | --- |
| `lesson:` | `[ветки](lesson:vetki-i-sliyaniya)` | урок по его slug |
| `page:` | `[шпаргалка](page:shpargalka)` | отдельная страница |
| `module:` | `[модуль 5](module:actions)` | обзор модуля |
| якорь | `[подробнее](#итоги)` | раздел этой же страницы |

Slug-и глобально уникальны: валидатор не пропустит дубликат.

## Как добавить урок (пошагово)

```bash
python3 tools/new_lesson.py --module git-osnovy --title "Теги и релизы"   # каркас
# заполнить теорию, код, схему, вопрос самопроверки
python3 build.py && python3 tools/validate.py --site site --strict
# запись в docs/CHANGELOG.md, коммит, push — CI соберёт и проверит сам
```

## Стиль текста

- Обращайтесь к читателю на «вы», короткими предложениями, без канцелярита.
- Каждую команду объясняйте: что делает, что изменится, как проверить.
- Пример вывода давайте в блоке `text`, чтобы читатель мог сверить со своим терминалом.
- Ошибки разбирайте с решением: «симптом → причина → команда».
- Вместо «просто» и «очевидно» — конкретное объяснение.
- Термины при первом упоминании давайте с переводом: «область подготовки (staging area)».

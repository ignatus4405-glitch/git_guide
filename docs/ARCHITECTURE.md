# Архитектура генератора курса

Документ объясняет, как устроен статический генератор сайта: какие шаги делает сборка,
где лежат данные и как расширять систему, не ломая существующее.

## Общая схема

```text
content/*.md ─┐
content/pages/*.md ─┐
tools/gen_diagrams.py ─┐
assets/ (css, js, img) ─┤
site.yml (метаданные) ─┴─► build.py ─► site/  (HTML, JSON, XML, SVG)
                                 └─► docs/STATE.md, docs/MANIFEST.json
```

Зависимостей нет: только стандартная библиотека Python. Это сознательное решение —
проект должен собираться на любом раннере и на любой машине без установки пакетов.

## Модули

| Модуль | Ответственность |
| --- | --- |
| `build.py` | точка входа: читает конфиг и контент, вызывает остальные модули, пишет файлы |
| `tools/yamlmini.py` | мини-парсер YAML-подмножества (конфиги, front matter) |
| `tools/frontmatter.py` | разбор блока `---` в начале markdown-файлов |
| `tools/content.py` | модель данных: `Page`, `Module`, `Site`; загрузка контента, разрешение ссылок |
| `tools/md.py` | Markdown → HTML: заголовки, код, таблицы, врезки, квизы, санитайзинг HTML |
| `tools/highlight.py` | подсветка синтаксиса: правила по языкам, полное сохранение текста |
| `tools/templates.py` | HTML-каркас: head, шапка, сайдбар, оглавление, подвал, поиск |
| `tools/gen_diagrams.py` | SVG-схемы как код; реестр `DIAGRAMS` — источник истины |
| `tools/gen_state.py` | генерация `docs/STATE.md` и `docs/MANIFEST.json` |
| `tools/validate.py` | проверки контента и собранного сайта (используется в CI) |
| `tools/test_build.py` | самотесты: парсеры, рендерер, полный цикл сборки, детерминизм |
| `tools/serve.py` | локальный HTTP-сервер предпросмотра |
| `tools/new_lesson.py` | генератор каркаса урока или страницы |

## Шаги сборки

1. **Конфиг.** `load_config()` читает `site.yml`, проверяет обязательные поля, заполняет умолчания.
2. **Контент.** `load_site()` разбирает `content/modules.yml`, уроки модулей и страницы
   `content/pages/*.md`. Для каждого файла вычисляются `slug`, `url`, объём, время чтения.
3. **Схемы.** `gen_diagrams.write_all()` генерирует SVG в `site/assets/img/diagrams/`.
4. **Ассеты.** Каталог `assets/` копируется в `site/assets/` как есть.
5. **Рендер страниц.** Для каждой страницы: подстановка токенов (`[[STATS]]`, `[[MODULE_MAP]]`,
   `[[MODULE_CARDS]]`), Markdown → HTML, обёртка в шаблон, оглавление из заголовков H2–H4.
6. **Индексы и фиды.** `search-index.json`, `sitemap.xml`, `feed.xml`, `robots.txt`, `404.html`.
7. **Метаданные сборки.** `build-info.json` + `docs/STATE.md` + `docs/MANIFEST.json`.

Сборка идемпотентна: одинаковый вход даёт побайтово одинаковый выход, кроме даты сборки
в `build-info.json` (это проверяется тестом `test_build_is_deterministic`).

## Ключевые контракты

### Ссылки

В markdown используются схемы, которые разрешает `Site.resolve()`:

| Схема | Куда ведёт | Пример |
| --- | --- | --- |
| `lesson:<slug>` | страница урока | `[ветки](lesson:vetki-i-sliyaniya)` |
| `page:<slug>` | отдельная страница | `[шпаргалка](page:shpargalka)` |
| `module:<id>` | обзор модуля | `[модуль 5](module:actions)` |
| обычный путь | файл относительно корня сайта | `![схема](assets/img/diagrams/three-trees.svg)` |

Относительные пути вычисляются от текущей страницы (`Page.prefix`), поэтому сайт работает
и из подкаталога `/git_guide/`, и из `file://`.

### Токены

`[[STATS]]`, `[[MODULE_MAP]]`, `[[MODULE_CARDS]]`, `[[LESSON_COUNT]]` подставляются в момент
рендера. Неизвестный токен оставляет предупреждение сборки — это ловится тестами и валидатором.

### Квизы

Блок `::: quiz` парсится в интерактивный компонент: `- (x) верный`, `- ( ) неверный`,
после вариантов — абзац-пояснение. Валидатор требует ровно один верный вариант
и наличие пояснения.

### Подсветка

`tools/highlight.py` устроен как «жадный сканер»: на каждой позиции пробуются правила языка
по порядку. Инвариант — исходный текст попадает в вывод ровно один раз; это проверяется
тестом `test_text_is_preserved` для всех поддерживаемых языков.

## Как расширять

**Новый язык подсветки.** Добавьте вызов `_add("lang", ...)` в `tools/highlight.py`
и при необходимости алиас в `_ALIASES`.

**Новый тип врезки.** Добавьте запись в `_ADMONITIONS` (`tools/md.py`) и класс стилей
в `assets/css/site.css`, затем используйте `::: имя Заголовок`.

**Новый шаг сборки.** Добавьте метод `render_*` в `Builder` и вызовите его из `Builder.run()`.
Если шаг пишет файлы — не забудьте про `self.write(...)`, иначе файл не попадёт в
`build-info.json` и проверку обязательных файлов.

**Новая проверка контента.** Добавьте правило в `validate_content()`; при необходимости
сделайте его предупреждением (`report.warn`), чтобы не ломать существующий контент.

**Новый генератор диаграмм.** Функция, возвращающая SVG-строку, строится на `Canvas`
(прямоугольники, стрелки, подписи, легенда). Не забудьте зарегистрировать её в `DIAGRAMS`
и проверить рендер: `python3 tools/gen_diagrams.py --out /tmp/svg`.

## Производительность

Полная сборка курса (24 урока, 13 схем) занимает меньше секунды на раннере GitHub Actions.
Поэтому оптимизации не нужны; при росте контента в 10 раз имеет смысл кэшировать
подсветку и параллелить рендер страниц.

# Разработка и добавление уроков

## Изменение содержания курса

Редактируйте `Course/lessons.json`. Не помещайте тексты уроков в XAML или C# — интерфейс должен оставаться независимым от содержания. JSON читается приложением из встроенного ресурса при запуске, поэтому приложение и курс распространяются вместе.

Урок содержит:

- `id` — уникальный неизменяемый идентификатор, например `22-advanced-logs`;
- `section`, `title`, `level`, `durationMinutes`, `lead`;
- `blocks` — упорядоченный список блоков `heading`, `text`, `bullet`, `code` или `note`; у каждого блока обязателен непустой `text`, у `code` и `note` можно добавить `title`;
- `diagram` — `title`, `caption` и не менее трёх шагов с полями `title` и `detail`; приложение рисует схему из этих шагов;
- `practice` — конкретное упражнение, которое безопасно выполнить в тестовом репозитории;
- `quiz` — вопрос, как минимум два варианта, нулевой индекс верного ответа `answerIndex` и объяснение ответа.

Пишите точные инструкции: называйте PowerShell или Git Bash, объясняйте, в какой папке выполнять команды, показывайте ожидаемое состояние и предупреждайте о разрушительных командах. Все URL, команды и placeholders должны быть очевидны читателю. Не вставляйте настоящие пароли, токены, ключи, email автора проекта или другие личные данные.

После редактирования JSON запустите:

```powershell
python -m unittest discover -s tests -v
python scripts/validate_course.py
```

В `tests/test_course_content.py` обновляйте тесты покрытия, если добавляется новая фундаментальная функция. Проверка JSON ловит синтаксические ошибки, дубликаты ID, неполные схемы и неверный индекс ответа.

## Изменение WPF-приложения

- `MainWindow.xaml` — компоновка и стили окна.
- `MainWindow.xaml.cs` — навигация, отрисовка блоков и прохождение теста.
- `Models/` — типы данных для курса.
- `Services/CourseService.cs` — загрузка встроенного JSON.
- `Services/ProgressStore.cs` — локальный файл выполненных уроков.

Не добавляйте сетевые зависимости или NuGet-пакеты без необходимости: курс рассчитан на офлайн-работу и сейчас не зависит от сторонних библиотек.

## Автоматическая сборка

`.github/workflows/build-windows.yml` запускается при push, pull request и вручную. Сначала на Ubuntu запускаются тесты и валидация курса; после этого Windows runner выполняет `dotnet publish` для `win-x64` и загружает ZIP `GitHubCourse-Windows-x64` с retention 14 дней. Изменения XAML/C# считаются готовыми только после успешного `build-windows` в Actions.

## Что умеет GitHub Pages

Pages публикует **статические файлы**: HTML, CSS, JavaScript, изображения, JSON. Никакого
серверного кода (PHP, Python, базы данных) здесь не выполняется — страницы отдаются как есть.

| Подходит | Не подходит |
| --- | --- |
| Документация, курсы, блоги | API с серверной логикой |
| Портфолио, лендинги | приложения с базой данных |
| Демо собранного фронтенда | фоновые задачи, cron на сервере |
| Отчёты, сгенерированные CI | приватный контент для авторизованных |

Ограничения, о которых стоит знать заранее: сайт публичный (для приватных репозиториев — только
на платных планах), мягкие лимиты по размеру репозитория и трафику, а сборка — только статика.

## Как включить

```text title="Через интерфейс"
Settings → Pages → Build and deployment
  Source: Deploy from a branch  → ветка gh-pages (или main, каталог /docs или /root)
  Source: GitHub Actions        → любой workflow с actions/deploy-pages
```

```bash title="Через API (нужны права admin на репозиторий)"
# включить публикацию из Actions
gh api -X POST repos/OWNER/REPO/pages -f build_type=workflow

# посмотреть текущие настройки
gh api repos/OWNER/REPO/pages --jq '{url: .html_url, source: .source, status: .status}'
```

::: tip Ветка или Actions
**Ветка** проще: положили файлы в `gh-pages` — сайт обновился. **Actions** гибче: можно
и запускать сборку (Jekyll, Astro, ваш генератор), и выполнять проверки до публикации.
Для сгенерированных сайтов (как этот курс) правильный выбор — Actions.
:::

## Ветка gh-pages: старый добрый способ

```bash title="Публикация из отдельной ветки"
python3 build.py --out public
cd public
git init -q && git add -A && git commit -m "publish"
git branch -M gh-pages
git remote add origin git@github.com:OWNER/REPO.git
git push -f origin gh-pages
```

Так публикуют «руками», из CI или из скрипта. Минус: `gh-pages` — служебная ветка, и
её история не связана с историей проекта; легко запутаться, что где лежит.

## Свой домен и HTTPS

```text title="Настройка домена"
1. Settings → Pages → Custom domain → example.com
2. У DNS-провайдера добавить записи:
   A    @    185.199.108.153 / .109.153 / .110.153 / .111.153
   CNAME www  <user>.github.io
3. Дождаться проверки DNS и включить Enforce HTTPS
```

GitHub создаёт файл `CNAME` в источнике публикации. Если сайт собирается Actions,
`CNAME` нужно добавлять в сборку самостоятельно — иначе домен будет сбрасываться:

```bash title="Кладём CNAME в сборку"
echo "example.com" > site/CNAME     # в build.py или шаге workflow после сборки
```

::: warning Частые ошибки с доменом
- `CNAME` не в корне опубликованного каталога → домен сбрасывается при следующем деплое.
- Не настроен `www` → часть посетителей получает 404.
- HTTPS включён до подтверждения домена → сертификат не выдаётся; подождите проверку DNS.
:::

## Что важно помнить про пути

Pages отдаёт сайт из подкаталога `/<repo>/`, поэтому **абсолютные пути вида `/css/site.css`
ломаются**. Используйте относительные ссылки (`../css/site.css`) или указывайте префикс.

Этот курс собран именно так: все внутренние ссылки относительные, поэтому сборка работает
и из подкаталога Pages, и из `file://`, и из локального сервера предпросмотра.

## Итоги

- Pages — бесплатный статический хостинг внутри GitHub; серверный код не поддерживается.
- Источник публикации: ветка или GitHub Actions (предпочтительно для сгенерированных сайтов).
- Свой домен требует DNS-записей, файла `CNAME` в сборке и включённого HTTPS.
- Сайт живёт в подкаталоге, поэтому относительные пути безопаснее абсолютных.

::: exercise Упражнение: опубликовать страницу
1. Создайте репозиторий с одним `index.html` (или соберите этот курс: `python3 build.py`).
2. Включите Pages: Settings → Pages → Source: GitHub Actions.
3. Добавьте workflow с `upload-pages-artifact` и `deploy-pages` (шаблон есть в следующем уроке).
4. Запушьте в `main` и получите ссылку `https://<user>.github.io/<repo>/`.
5. Проверьте, что страницы открываются: главная, любой урок, страница 404 на несуществующем адресе.
:::

::: quiz Почему абсолютная ссылка `/assets/css/site.css` может не работать на Pages?
- ( ) Pages не поддерживает CSS
- (x) Сайт публикуется из подкаталога /<repo>/, и корень домена — не корень проекта
- ( ) GitHub перезаписывает абсолютные пути при деплое

При публикации из подкаталога `/repo/` абсолютный путь `/assets/...` указывает на корень
домена, где файлов проекта нет. Относительные пути работают в обоих случаях.
:::

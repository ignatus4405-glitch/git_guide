## Как проходить

Отвечайте, не подглядывая в уроки: цель — найти пробелы, а не поставить галочку. После
неверного ответа раскрывается пояснение со ссылкой на материал. Если ошибок больше пяти —
вернитесь к соответствующим модулям.

::: tip Про формат
Каждый вопрос имеет один верный вариант. Пояснение показывается сразу после выбора ответа
и остаётся на странице: можно вернуться и перечитать.
:::

## Модуль 1. Основы

::: quiz Что означает, что Git — распределённая система контроля версий?
- ( ) История хранится на сервере, а локально есть только последняя версия файлов
- (x) Полная история есть у каждого участника, коммиты создаются локально без сети
- ( ) Каждый файл хранится отдельно, а версии — в облаке

Распределённость означает, что клон содержит всю историю, а `commit` работает без обращений к серверу.

Вопрос из урока [«Что такое Git»](lesson:chto-takoe-git).
:::

::: quiz Что попадёт в следующий коммит после `git add a.txt` и правки `b.txt`?
- ( ) Оба файла: и a.txt, и b.txt
- (x) Только a.txt: в индекс попал лишь он
- ( ) Только b.txt: он изменён позже

Коммит берёт содержимое индекса. Правки `b.txt` останутся в рабочем каталоге и потребуют отдельного `git add`.

Вопрос из урока [«Первый репозиторий»](lesson:pervyy-repozitoriy).
:::

::: quiz Зачем нужен файл .gitignore?
- ( ) Удалять ненужные файлы из рабочего каталога
- (x) Не показывать и не добавлять в историю неотслеживаемые файлы по шаблонам
- ( ) Хранить список исключений для ветвления

Игнор действует только на неотслеживаемые файлы и не удаляет их с диска.

Вопрос из урока [«Первый репозиторий»](lesson:pervyy-repozitoriy).
:::

## Модуль 2. История и ветки

::: quiz Что покажет `git log --oneline --graph --all`?
- ( ) Только коммиты текущей ветки в порядке времени
- (x) Граф истории всех веток и ссылок с метками и «однострочными» коммитами
- ( ) Список файлов, изменённых в последнем коммите

`--graph` рисует ветвление, `--decorate`/`--all` добавляют метки и все ссылки.

Вопрос из урока [«История коммитов»](lesson:istoriya-i-log).
:::

::: quiz Когда слияние проходит как fast-forward?
- ( ) Когда обе ветки изменили одни и те же строки
- (x) Когда целевая ветка не расходилась с текущей: указатель просто переезжает вперёд
- ( ) Когда задан флаг --no-ff

Fast-forward возможен только при отсутствии расхождения; `--no-ff` его как раз запрещает.

Вопрос из урока [«Ветки и слияния»](lesson:vetki-i-sliyaniya).
:::

::: quiz Что означает `git checkout --theirs file` во время merge?
- ( ) Оставить вашу версию файла целиком
- (x) Взять версию файла из вливаемой ветки
- ( ) Объединить обе версии построчно

«theirs» — вливая ветка, «ours» — текущая. В rebase смысл меняется местами.

Вопрос из урока [«Конфликты слияния»](lesson:konflikty).
:::

::: quiz Какая команда безопасна для отмены уже опубликованного коммита?
- ( ) git reset --hard HEAD~1
- (x) git revert <sha>
- ( ) git rebase -i и drop

`reset` и `rebase` переписывают историю; `revert` создаёт новый коммит-отмену.

Вопрос из урока [«rebase, отмена и спасение работы»](lesson:otmena-i-rebase).
:::

::: quiz Где искать коммиты, «пропавшие» после неудачного reset?
- ( ) В .gitignore
- (x) В git reflog
- ( ) В git status

Reflog хранит перемещения ссылок и позволяет вернуть состояние через `git switch -c rescue <sha>`.

Вопрос из урока [«rebase, отмена и спасение работы»](lesson:otmena-i-rebase).
:::

## Модуль 3. GitHub

::: quiz Что изменится в рабочем каталоге после `git fetch`?
- ( ) Файлы обновятся до состояния origin/main
- (x) Ничего: обновятся только удалённые ссылки и объекты
- ( ) Автоматически создастся merge-коммит

`fetch` безопасен: файлы меняются только после merge/rebase (то есть после `pull`).

Вопрос из урока [«Удалённые репозитории»](lesson:remote-i-sinhronizatsiya).
:::

::: quiz Чем `--force-with-lease` лучше `--force`?
- ( ) Он быстрее выполняет отправку
- (x) Он откажется перезаписывать ветку, если на сервере появились чужие коммиты
- ( ) Он автоматически создаёт резервную ветку

`--force-with-lease` сравнивает ожидаемое состояние удалённой ветки с фактическим и защищает чужую работу.

Вопрос из урока [«Удалённые репозитории»](lesson:remote-i-sinhronizatsiya).
:::

::: quiz Что позволяет squash-слияние PR?
- ( ) Сохранить все коммиты PR отдельными коммитами в main
- (x) Объединить все коммиты PR в один коммит с сообщением PR
- ( ) Запретить слияние без ревью

Squash склеивает коммиты ветки в один — удобно для «шумных» коротких PR.

Вопрос из урока [«Pull Request»](lesson:pull-request).
:::

::: quiz Зачем включать branch protection на main?
- ( ) Чтобы ускорить слияния
- (x) Чтобы в основную ветку нельзя было попасть без PR, ревью и зелёных проверок
- ( ) Чтобы автоматически удалять старые ветки

Правила ветки превращают договорённости в формальные ограничения.

Вопрос из урока [«GitHub Flow и gh CLI»](lesson:gh-cli-i-flow).
:::

::: quiz Ревьюер просит правки в открытом PR. Как их отправить?
- ( ) Создать новый PR взамен старого
- (x) Дописать коммиты в ту же ветку и запушить: PR обновится
- ( ) Сделать force-push в main

PR отслеживает ветку-источник: новые коммиты и push автоматически обновляют его.

Вопрос из урока [«Pull Request»](lesson:pull-request).
:::

## Модуль 4. Команда

::: quiz Что такое CODEOWNERS?
- ( ) Файл со списком мейнтейнеров репозитория для README
- (x) Файл, по которому GitHub автоматически назначает ревьюеров для конкретных путей
- ( ) Список авторов коммитов

`CODEOWNERS` связывает пути с людьми или командами; в связке с правилами ветки ревью становится обязательным.

Вопрос из урока [«Code review»](lesson:code-review).

::: quiz Какой шаблон issue самый полезный для багов?

- ( ) Только скриншот

Воспроизводимость — главное условие, при котором задачу можно взять в работу.

Вопрос из урока [«Issues, Projects и шаблоны»](lesson:issues-i-proekty).

## Модуль 5. Actions

::: quiz Зачем нужен шаг `actions/checkout`?
- ( ) Чтобы установить зависимости
- (x) Чтобы скопировать содержимое репозитория на чистую машину runner-а
- ( ) Чтобы включить кэш

Runner стартует без файлов проекта: без checkout команды сборки не найдут исходники.

Вопрос из урока [«Основы Actions»](lesson:osnovy-actions).
:::

::: quiz Как задать зависимость job-а build от job-а test?
- ( ) dependencies: test
- (x) needs: test
- ( ) after: test

Ключ `needs` задаёт порядок выполнения job-ов.

Вопрос из урока [«Основы Actions»](lesson:osnovy-actions).
:::

::: quiz От чего должен зависеть ключ кэша зависимостей?
- ( ) От времени запуска workflow
- (x) От файла блокировки зависимостей (requirements.txt, package-lock.json)
- ( ) От имени ветки

Иначе кэш будет переиспользовать устаревшие зависимости и маскировать проблемы.

Вопрос из урока [«Матрицы, кэш, артефакты»](lesson:matrica-kesh-artefakty).
:::

::: quiz Почему секреты недоступны в workflow, запущенном из форка?
- ( ) Форки не могут запускать Actions
- (x) Иначе код из чужого PR получил бы доступ к вашим ключам
- ( ) Секреты доступны только при ручном запуске

Прогоны из форков получают `GITHUB_TOKEN` с правами только на чтение и не видят другие секреты.

Вопрос из урока [«Матрицы, кэш, артефакты»](lesson:matrica-kesh-artefakty).
:::

::: quiz Зачем в авто-коммите документации указывают `[skip ci]`?
- ( ) Чтобы коммит не подписывался
- (x) Чтобы коммит не запускал новый прогон workflow и не создал петлю
- ( ) Чтобы ускорить сборку

Без этой метки авто-коммит запускает workflow снова — и так по кругу.

Вопрос из урока [«Разбор: как собирается этот курс»](lesson:ci-kursa).
:::

## Модуль 6. Pages

::: quiz Почему на Pages не работает абсолютный путь `/assets/style.css`, если сайт в подкаталоге?
- ( ) Pages удаляет абсолютные пути
- (x) `/` указывает на корень домена, а файлы проекта лежат в /<repo>/
- ( ) Абсолютные пути работают только при включённом HTTPS

Проектный сайт публикуется из подкаталога; относительные ссылки работают всегда.

Вопрос из урока [«GitHub Pages»](lesson:pages-osnovy).
:::

::: quiz Какие права нужны workflow для публикации на Pages?
- ( ) contents: write
- (x) pages: write и id-token: write
- ( ) actions: write

`pages: write` разрешает публикацию, `id-token: write` выдаёт OIDC-токен, которым подтверждается деплой.

Вопрос из урока [«Публикация из GitHub Actions»](lesson:deploy-iz-actions).
:::

::: quiz Что произойдёт, если в сборке нет файла CNAME, а домен настроен?
- ( ) Сайт будет доступен по IP-адресу
- (x) Пользовательский домен сбросится к стандартному адресу Pages
- ( ) HTTPS перестанет работать навсегда

`CNAME` — часть публикуемого артефакта: если его нет, настройка домена теряется при следующем деплое.

Вопрос из урока [«GitHub Pages»](lesson:pages-osnovy).
:::

## Модуль 7. Безопасность

::: quiz Что можно использовать вместо пароля аккаунта для `git push` по HTTPS?
- ( ) Только пароль с 2FA
- (x) Personal access token (fine-grained) или SSH-ключ
- ( ) Ничего: push по HTTPS запрещён

Пароли для Git-операций не принимаются; нужны токены или SSH.

Вопрос из урока [«Аутентификация»](lesson:autentifikatsiya).
:::

::: quiz Секрет попал в публичный репозиторий. Что делать первым?
- ( ) Удалить коммит и сделать force-push
- (x) Отозвать и перевыпустить секрет
- ( ) Добавить файл в .gitignore

Значение могло быть скопировано автоматическими сканерами; отзыв — единственная надёжная мера.

Вопрос из урока [«Секреты в Actions»](lesson:sekrety-i-peremennye).
:::

::: quiz Что хранит родительский репозиторий при использовании подмодулей?
- ( ) Полную копию содержимого подмодуля
- (x) Ссылку на конкретный коммит подмодуля и адрес в .gitmodules
- ( ) Только имя каталога

В индексе подмодуль — «gitlink» с SHA: обновление зависимости становится отдельным изменением.

Вопрос из урока [«Большие файлы, LFS, подмодули»](lesson:bolshie-fayly-i-podmoduli).
:::

::: quiz Как безопасно ускорить клон монорепозитория, если нужен один каталог?
- ( ) git clone --depth 1 и потом искать файлы вручную
- (x) git clone --filter=blob:none --sparse, затем git sparse-checkout set <каталог>
- ( ) Скопировать каталог с сервера через архив

Комбинация частичного клона и sparse-checkout даёт минимальный объём скачивания и рабочей копии.

Вопрос из урока [«Большие файлы, LFS, подмодули»](lesson:bolshie-fayly-i-podmoduli).
:::

## Модуль 8. Продвинутое

::: quiz Зачем указывать `core.hooksPath .githooks`?
- ( ) Чтобы хуки работали только на сервере
- (x) Чтобы хранить хуки в репозитории вместо локального .git/hooks
- ( ) Чтобы отключить проверки перед коммитом

Каталог `.git` не клонируется, поэтому хуки выносят в версионируемый каталог и подключают настройкой.

Вопрос из урока [«Хуки, шаблоны и .gitattributes»](lesson:hooki-i-shablon).
:::

::: quiz Какую роль играет .gitattributes в проблеме «весь файл изменён»?
- ( ) Он удаляет лишние символы перевода строки
- (x) Он задаёт нормализацию переводов строк (text=auto eol=lf) и тип файлов
- ( ) Он отключает подсветку в GitHub

Настройка `text=auto eol=lf` приводит переводы строк к одному виду и убирает ложные диффы.

Вопрос из урока [«Хуки, шаблоны и .gitattributes»](lesson:hooki-i-shablon).
:::

::: quiz Почему обычный `git push` не создаёт релиз по тегу?
- ( ) Потому что теги всегда нужно создавать в веб-интерфейсе
- (x) Потому что теги не отправляются с веткой: нужен push тега или --tags
- ( ) Потому что релизы создаются только из main

Ветка и тег — разные ссылки. Пока тег не отправлен, события `push: tags` не будет.

Вопрос из урока [«Теги, релизы и semver»](lesson:tegi-relizy-semver).
:::

::: quiz Какой объект Git содержит имена файлов?
- ( ) Блоб
- (x) Дерево
- ( ) Коммит

Блоб хранит содержимое без имени; имена и структура каталогов — в объектах-деревьях.

Вопрос из урока [«Git изнутри»](lesson:git-iznutri).
:::

::: quiz Что означает semver-версия 2.4.1 → 2.5.0?
- ( ) Критическая ошибка безопасности закрыта
- (x) Добавлена новая функциональность без несовместимых изменений
- ( ) Изменён публичный API несовместимым образом

MINOR растёт при добавлении функциональности, MAJOR — при несовместимости, PATCH — при исправлениях.

Вопрос из урока [«Теги, релизы и semver»](lesson:tegi-relizy-semver).
:::

это лучший тренажёр после курса. Следующие темы для роста — на странице
[«Материалы и что дальше»](page:resursy).

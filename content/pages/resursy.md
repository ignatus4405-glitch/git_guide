## Практика

- **`git help <команда>`** и `git <команда> -h` — локальная справка, которая работает без интернета.
- **Тренажёр Learn Git Branching** (`learngitbranching.js.org`) — визуальная песочница для веток, rebase и cherry-pick.
- **`git log --help`** — читайте разделы «Discussion»: они объясняют не синтаксис, а смысл.
- **Собственный проект** — единственный способ довести навык до автоматизма: заведите репозиторий,
  включите CI, защиту ветки и Pages.

## Темы для дальнейшего роста

::: columns
### DevOps и поставка

- GitHub Actions: reusable workflows, composite actions, self-hosted runners.
- Environments и стратегии деплоя: blue-green, canary.
- Окружения и инфраструктура как код (Terraform, Helm).
- Наблюдаемость: что делать, когда деплой прошёл, а сервис лежит.

### Архитектура и масштаб

- Монорепозитории: sparse-checkout, CODEOWNERS, разделение CI по путям.
- Полирепозитории: версионирование внутренних библиотек, релизы по тегам.
- Trunk-based development и feature flags.
- Semantic-release и автоматическое версионирование.
:::

::: columns
### Безопасность

- Supply chain: pinned-версии actions, SBOM, attestations.
- OIDC вместо долгоживущих секретов.
- CodeQL и статический анализ в CI.
- Политики организации: rulesets, required workflows.

### Качество процесса

- Conventional Commits и автоматический changelog.
- Trunk-based с маленькими PR и feature-флагами.
- Метрики: время до ревью, частота слияний, DORA-показатели.
- Документирование решений (ADR) — в том же репозитории.
:::

## Чек-лист «мой проект настроен правильно»

- [ ] В репозитории есть `README.md`, `LICENSE`, `CONTRIBUTING.md`.
- [ ] Настроены `.gitignore` и `.gitattributes`.
- [ ] `main` защищена: обязательный PR, ревью и зелёные проверки.
- [ ] CI запускается на push и PR, прогоняет тесты и сборку.
- [ ] Секреты — только в GitHub Secrets; включены secret scanning и push protection.
- [ ] Есть шаблоны issue и PR, при необходимости `CODEOWNERS`.
- [ ] Релизы выпускаются тегами с описанием и артефактами.
- [ ] Документация обновляется автоматически или вместе с кодом.

::: tip Финальное упражнение курса
Выберите небольшой проект (свой или открытый с меткой `good first issue`) и пройдите весь путь
целиком: форк → ветка → коммиты → PR с описанием → ревью → слияние → тег `v0.1.0` → релиз →
публикация на Pages → включённые проверки безопасности. После этого Git и GitHub перестанут быть
инструментами «по инструкции» и станут частью вашей обычной работы.
:::

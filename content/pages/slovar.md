## Основы модели Git

| Термин | Определение |
| --- | --- |
| **Репозиторий** (repository) | Каталог, в котором Git хранит историю. Технически — подкаталог `.git` со всеми объектами и ссылками. |
| **Блоб** (blob) | Объект, содержащий содержимое файла без имени. Адресуется хешем содержимого. |
| **Дерево** (tree) | Объект, описывающий каталог: список записей «режим, тип, SHA, имя». Здесь хранятся имена файлов. |
| **Коммит** (commit) | Снимок состояния проекта: ссылка на дерево, родители, автор, дата, сообщение. |
| **Тег** (tag) | Неподвижная метка на объект. Аннотированный тег — отдельный объект с автором и сообщением. |
| **SHA / хеш** | Идентификатор объекта: `sha1("тип размер\0содержимое")`. Изменение содержимого меняет SHA. |
| **HEAD** | Указатель на текущий коммит (обычно через ветку). «Отсоединённый HEAD» — прямая ссылка на коммит. |
| **Ссылка** (ref) | Именованный указатель: ветка, тег, `refs/remotes/origin/main`. Файл в `.git/refs/` или строка в `packed-refs`. |
| **Индекс / область подготовки** (index, staging area) | Промежуточное состояние: то, что попадёт в следующий коммит. |
| **Рабочий каталог** (working tree) | Файлы проекта на диске в том виде, в котором вы их редактируете. |
| **FETCH_HEAD / ORIG_HEAD** | Служебные ссылки: результат последнего `fetch` и состояние до опасной операции. |

## Ветвление и история

| Термин | Определение |
| --- | --- |
| **Ветка** (branch) | Подвижная метка на коммит, перемещается автоматически при новом коммите. |
| **Слияние** (merge) | Соединение историй двух веток. Может быть fast-forward или merge-коммитом. |
| **Fast-forward** | Ситуация, когда целевая ветка не расходилась с текущей: указатель просто переезжает вперёд. |
| **Merge-коммит** | Коммит с двумя и более родителями, фиксирующий результат слияния. |
| **Конфликт** (conflict) | Пересечение правок, требующее решения человеком; Git расставляет маркеры `<<<<<<<`. |
| **Rebase** | Перенос коммитов на другую базу с созданием новых коммитов (меняются SHA). |
| **Cherry-pick** | Копирование одного конкретного коммита в текущую ветку. |
| **Detached HEAD** | Состояние, когда HEAD указывает на коммит, а не на ветку: новые коммиты «повиснут» без метки. |
| **Упаковка** (gc, packfile) | Сжатие объектов в `.pack` с использованием дельт. |
| **Висячий объект** (dangling) | Объект, на который не ссылается ни одна ссылка и reflog; удаляется при сборке мусора. |

## Удалённые репозитории

| Термин | Определение |
| --- | --- |
| **Remote** | Именованный адрес другого репозитория. `origin` — адрес по умолчанию при клонировании. |
| **Upstream** | Репозиторий, от которого сделан форк; либо ветка, за которой следит локальная. |
| **Клон** (clone) | Локальная копия репозитория вместе со всей историей. |
| **Форк** (fork) | Серверная копия чужого репозитория в вашем аккаунте. |
| **Fetch** | Скачивание объектов и обновление удалённых ссылок без изменения рабочей копии. |
| **Pull** | `fetch` + слияние (или rebase) с текущей веткой. |
| **Push** | Отправка локальных коммитов в удалённую ветку. |
| **Force-with-lease** | Безопасный force-push: отказ, если на сервере есть неожиданные коммиты. |
| **Tracking branch** | Локальная ветка, за которой закреплена удалённая (upstream). |

## GitHub как платформа

| Термин | Определение |
| --- | --- |
| **Pull Request (PR)** | Предложение внести изменения из вашей ветки в другую, с обсуждением, ревью и проверками. |
| **Issue** | Задача, баг или идея; единица работы в проекте. |
| **Milestone** | Группа issue/PR, привязанная к релизу или сроку. |
| **Projects** | Канбан-доски GitHub для планирования работы. |
| **CODEOWNERS** | Файл, назначающий владельцев путей: их автоматически добавляют ревьюерами. |
| **Branch protection** | Правила ветки: обязательный PR, ревью, зелёные проверки, запрет force-push. |
| **Required status checks** | Проверки CI, которые обязаны пройти до слияния. |
| **Squash merge** | Слияние PR с объединением всех коммитов в один. |
| **Release** | Тег плюс описание, артефакты и заметки об изменениях. |
| **Actions / Workflow / Job / Step** | Встроенный CI/CD: файл автоматизации, набор задач на одном runner-е, отдельный шаг задачи. |
| **Runner** | Виртуальная машина, на которой выполняется job. |
| **Artifact** | Файл, сохранённый из прогона workflow (сборка, отчёты, логи). |
| **Secrets / Variables** | Защищённые значения и обычные настройки, доступные в workflow. |
| **Environment** | Набор правил и секретов для деплоя: обязательное одобрение, ограничение по ветвям, URL. |
| **GITHUB_TOKEN** | Токен, автоматически выдаваемый прогону; его права задаются блоком `permissions`. |
| **Pages** | Бесплатный статический хостинг GitHub; источник — ветка или артефакт из Actions. |
| **Dependabot** | Бот, который обновляет зависимости и сообщает об уязвимостях. |
| **CodeQL / secret scanning** | Встроенный статический анализ кода и поиск секретов в репозитории. |

## Практики и процессы

| Термин | Определение |
| --- | --- |
| **GitHub Flow** | Модель работы: `main` всегда готова, задача — в ветке, изменения — через PR. |
| **Trunk-based development** | Модель, где все изменения часто идут в основную ветку короткими порциями, а неготовое скрывается флагами. |
| **Code review** | Проверка изменений коллегами до слияния: поиск дефектов, распространение знаний. |
| **Conventional Commits** | Соглашение о сообщениях: `feat:`, `fix:`, `docs:`. Позволяет автоматизировать changelog. |
| **Semver** | Семантическое версионирование `MAJOR.MINOR.PATCH` с правилами, когда какая цифра растёт. |
| **Changelog** | Документ с описанием изменений по версиям, обычно в формате Keep a Changelog. |
| **CI / CD** | Непрерывная интеграция (проверки на каждый push) и непрерывная доставка (автоматическая публикация). |
| **LFS** | Large File Storage: содержимое больших файлов хранится снаружи, в Git — указатели. |
| **Submodule** | Чужой репозиторий внутри вашего, зафиксированный на конкретном коммите. |
| **Sparse checkout** | Рабочая копия только части дерева репозитория. |
| **OIDC** | Способ получить короткоживущие креды из облака без хранения долгоживущих токенов. |
| **Pre-commit hook** | Локальная проверка, запускаемая перед созданием коммита. |
| **Reflog** | Журнал перемещений ссылок: помогает восстановить «потерянные» коммиты. |

## Сначала — решение, потом команды

Переписывание истории — операция с последствиями: меняются SHA всех затронутых коммитов,
ломаются ссылки, у коллег появляются расхождения. Поэтому порядок такой:

1. **Отозвать секрет** (если это секрет) — до любых манипуляций с историей.
2. **Оценить объём:** нужно ли чистить всю историю или достаточно откатить последний коммит.
3. **Согласовать** переписывание с командой: время, ветки, форки.
4. **Заблокировать запись** на время работы (например, включить защиту веток) — иначе слияния вернут старые коммиты.
5. **Переписать, проверить, опубликовать** и попросить коллег переклонировать репозиторий.
6. **Добавить защиту**, чтобы проблема не повторилась.

::: warning Когда историю трогать не нужно
- Секрет был добавлен, но ещё **не запушен**: достаточно `git commit --amend` или
  `git reset` в локальной ветке.
- В коммите есть чувствительная информация, но репозиторий приватный и не расшаривался:
  часто достаточно отозвать секрет и продолжить без переписывания.
- Секрет был в коде, но значение уже отозвано и недействительно: чистка нужна только
  если это требование политики или аудита.
:::

## Способы посмотреть, что утекло

```bash title="Аудит истории"
# найти файл в истории
git log --all --oneline -- .env
git log --all -p -S "API_KEY" --pretty=format:"%h %ad %an"

# посмотреть, какие большие файлы есть в истории
git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '$1=="blob" && $3 > 2000000 {print $3, $4}' | sort -rn | head -20

# проверить, какие ветки и теги указывают на «плохие» коммиты
git branch -a --contains <sha>; git tag --contains <sha>
```

## git filter-repo: рекомендуемый инструмент

`git filter-repo` заменил `git filter-branch` (тот официально не рекомендуется: крайне медленный
и легко ломает историю). Устанавливается одним файлом или пакетом.

```bash title="Установка"
pipx install git-filter-repo     # или: brew install git-filter-repo / apt install git-filter-repo
```

```bash title="Удалить файл из всей истории"
git clone --mirror git@github.com:OWNER/REPO.git repo-clean.git
cd repo-clean.git
git filter-repo --invert-paths --path .env --path config/secrets.yml
git log --all --oneline -- .env        # пусто — файла в истории больше нет

cd ..
git clone repo-clean.git repo-verify
# проверяем, что сборка/тесты проходят, история на месте
```

```bash title="Заменить конкретные значения во всей истории"
cat > replace.txt <<'EOF'
old-token-value==>REDACTED
sk_live_12345==>REDACTED
EOF
git filter-repo --replace-text replace.txt
```

::: tip Проверка перед публикацией
Всегда работайте на **зеркальной копии** (`--mirror`), проверяйте результат в отдельном клоне
и только потом заменяйте удалённый репозиторий. Тогда ошибка в фильтре не уничтожит оригинал.
:::

## Публикация переписанной истории

```bash title="Замена удалённой истории"
git push --force --all
git push --force --tags
```

Требования после этого:

- **Предупредить команду.** Коллегам нужно переклонировать репозиторий (или аккуратно
  `git fetch && git rebase --onto`), иначе они вернут старые коммиты своим push-ом.
- **Обновить форки.** Форки хранят свою копию истории: их нужно синхронизировать или удалить.
- **Проверить кэши GitHub.** Старые коммиты могут оставаться доступны по прямым ссылкам
  до обращения в поддержку; GitHub рекомендует после утечки также обращаться в Support.
- **Включить запрет force-push** на основных ветвях, чтобы исключить повторение.

## Профилактика

| Мера | Что предотвращает |
| --- | --- |
| `push protection` и secret scanning | попадание известных форматов секретов в репозиторий |
| pre-commit-хук с проверкой секретов | коммит с ключом локально |
| `.gitignore` для `.env`, `*.pem`, `credentials*` | случайное добавление файлов |
| шаблоны и документация (`CONTRIBUTING`) | «наивные» способы хранения конфигураций |
| запрет force-push на `main` и `release/*` | перезапись общей истории |
| подпись коммитов и обязательное ревью | скрытые изменения в основной ветке |
| ротация ключей по расписанию | долгую жизнь скомпрометированных секретов |

```bash title="Хук pre-commit: минимальный вариант"
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
PATTERNS='ghp_[A-Za-z0-9]{36}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----'
if git diff --cached | grep -E "^\+" | grep -Eq "$PATTERNS"; then
  echo "Коммит отклонён: обнаружен похожий на секрет фрагмент."
  exit 1
fi
EOF
chmod +x .git/hooks/pre-commit
```

::: danger Удаление ≠ безопасность
Очистка истории убирает значение из репозитория, но не делает секрет недействительным.
Если секрет был публичным хотя бы минуту, считайте его скомпрометированным навсегда.
:::

## Итоги

- Переписывание истории — крайняя мера: сначала отзыв секрета, потом оценка, потом команда.
- Основной инструмент — `git filter-repo` (`--invert-paths`, `--replace-text`), на зеркальной копии.
- Публикация требует `--force` и предупреждения команды: у всех появляются другие SHA.
- Профилактика надёжнее лечения: push protection, хуки, `.gitignore`, правила веток, ротация.
- Старые данные могут сохраняться в кэшах и форках — учитывайте это при оценке риска.

::: exercise Упражнение: чистка истории в песочнице
1. Создайте локальный репозиторий, добавьте файл `.env` с «секретом», закоммитьте и запушьте в тестовый репозиторий.
2. Добавьте ещё два коммита, чтобы «секрет» оказался не в последнем коммите.
3. Клонируйте репозиторий зеркально (`--mirror`) и удалите `.env` из истории командой `git filter-repo --invert-paths --path .env`.
4. Проверьте чистоту: `git log --all --oneline -- .env` и `git rev-list --objects --all | grep .env`.
5. Опубликуйте (`--force --all`), затем клонируйте заново и убедитесь, что файла нет ни в одном коммите.
:::

::: quiz Нужно ли переписывать историю, если секрет утёк, но уже отозван и заменён?
- ( ) Нет, отзыва достаточно во всех случаях
- (x) Зависит от политики: если значение недействительно, чистка нужна не всегда
- ( ) Да, иначе GitHub заблокирует репозиторий

Отозванный секрет не даёт доступа, поэтому чистка — вопрос требований безопасности
и аудита проекта. Если политика требует, чтобы значения не встречались в истории, —
чистим; иначе достаточно ротации и профилактики.
:::

## Что такое история в Git

История — это направленный граф коммитов. Каждый коммит знает своих родителей, поэтому Git
всегда может показать путь от текущего состояния назад. Всё остальное (`git log`, ветки, теги) —
удобные способы перемещаться по этому графу.

```bash title="Базовые форматы"
git log                                  # полный: автор, дата, сообщение, хеш
git log --oneline                        # по коммиту в строке
git log --oneline --graph --decorate --all   # граф: видно ветвление и метки
```

Пример вывода:

```text title="git log --oneline --graph --decorate --all"
* 9f2a1c4 (HEAD -> main, origin/main) feat: добавить экспорт отчёта
*   4c1d8e0 Merge branch 'fix/limits'
|\
| * 71b3m90 (fix/limits) fix: ограничить размер страницы
* | 2a8f1b2 docs: обновить описание API
|/
* 18c0aef chore: обновить зависимости
```

Как это читать:

- `*` — коммит, `|\` и `|/` — ветвление и слияние;
- слева от скобок — метки: `HEAD` (где вы), `main`, `origin/main`, имя ветки;
- слитный `Merge branch 'fix/limits'` — merge-коммит с двумя родителями.

## Фильтрация: найти нужный коммит

```bash title="Полезные фильтры"
git log --author="Анна"                  # коммиты конкретного автора
git log --since="2 weeks ago" --oneline  # за последние две недели
git log -- path/to/file.py               # история одного файла
git log --grep="кэш" -i                  # поиск по тексту сообщения
git log -S "MAX_RETRIES"                 # коммиты, где менялось содержимое строки
git log -p -1                            # изменения последнего коммита
```

`-S` (pickaxe) — самый мощный фильтр: он находит коммиты, в которых строка появилась или
исчезла. Это лучший способ ответить на вопрос «когда и кем был добавлен этот параметр?».

::: tip Формат вывода под свою задачу
`git log --pretty=format:"%h %ad %an %s" --date=short` — компактный список.
Сохраните как алиас: `git config --global alias.lgs 'log --pretty=format:"%h %ad %an %s" --date=short'`.
:::

## HEAD, SHA и ссылки

```bash title="Как адресовать коммиты"
git show 9f2a1c4            # коммит по короткому SHA
git show HEAD               # текущий коммит
git show HEAD~1             # родитель текущего
git show HEAD~3             # три коммита назад
git show main@{yesterday}   # где была ветка вчера (reflog)
```

| Обозначение | Что значит |
| --- | --- |
| `HEAD` | указатель на текущий коммит/ветку |
| `HEAD~2` | два коммита назад по первому родителю |
| `HEAD^2` | второй родитель (актуально только для merge-коммитов) |
| `origin/main` | состояние удалённой ветки на момент последнего `fetch` |
| `v1.2.0` | тег (неподвижная метка) |

## git show, git blame, git diff

```bash title="Разбор отдельных изменений"
git show HEAD                # содержимое коммита: дифф + метаданные
git diff main..origin/main   # что прилетит, если сделать pull
git diff HEAD~1 --stat       # только список файлов и счётчик строк
git blame -L 40,60 build.py  # кто и когда менял строки 40–60
git log --follow -- README.md   # история файла даже после переименований
```

`git blame` часто воспринимают как инструмент поиска виноватых. На практике это инструмент
контекста: он открывает коммит рядом со строкой, а в сообщении обычно написано, зачем она появилась.

![Схема: устройство коммита, дерева и блобов](assets/img/diagrams/commit-internals.svg "История — цепочка снимков: коммит → дерево → файлы")

::: warning Частая ошибка: git log показывает не то, что ожидали
По умолчанию `git log` показывает только текущую ветку. Чтобы увидеть все ветки —
`git log --all`; чтобы увидеть коммиты, «потерянные» после reset или rebase — `git reflog`.
:::

## Итоги

- История — граф снимков; `--graph --decorate --all` показывает его целиком.
- Фильтруйте историю: `--author`, `--since`, `-- path`, `--grep`, `-S`.
- Адресация коммитов: SHA, `HEAD`, `HEAD~N`, `HEAD^2`, теги, `branch@{time}`.
- `git blame` и `git show` дают контекст: зачем строка появилась и что было раньше.

::: exercise Упражнение: расследование истории
1. Клонируйте любой публичный репозиторий (например, `git clone https://github.com/git/git`).
2. Найдите в нём пять самых «горячих» файлов: `git log --pretty=format: --name-only | sort | uniq -c | sort -rn | head -5`.
3. Выберите один файл и посмотрите его историю с `--follow`.
4. Используйте `git log -S "<строка>" --oneline` и найдите коммит, который добавил эту строку.
5. Откройте его через `git show <sha>` и объясните (себе) контекст изменения.
:::

::: quiz Что покажет команда `git log -S "DATABASE_URL" --oneline`?
- ( ) Коммиты, в сообщении которых есть слово DATABASE_URL
- (x) Коммиты, где строки с DATABASE_URL добавлялись или удалялись
- ( ) Текущее содержимое файлов с DATABASE_URL

`-S` ищет по изменениям содержимого (pickaxe), а не по тексту сообщений — для сообщений нужен `--grep`.
:::

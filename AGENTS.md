# AGENTS.md — протокол работы над курсом

Этот файл — обязательная инструкция для любого, кто продолжает работу над репозиторием:
человека или AI-агента. Он отвечает на три вопроса: как собрать, что проверить, что обновить
после изменения. Читайте вместе с `docs/STATE.md` (актуальная карта репозитория) и
`docs/CHANGELOG.md` (журнал изменений).

## 1. Быстрый старт за 30 секунд

```bash
git switch -c feat/korotkoe-imya      # своя ветка, никогда не прямо в main
python3 build.py                     # собрать сайт в ./site
python3 tools/serve.py --port 8000   # посмотреть локально (0.0.0.0:8000)
python3 tools/validate.py --site site --strict   # проверки контента и ссылок
python3 tools/test_build.py          # 35 самотестов генератора
```

Зависимостей нет: нужен только Python 3.10+. Всё, что используется, — стандартная библиотека.

## 2. Инварианты, которые нельзя ломать

1. **Сборка без зависимостей.** Не добавляйте внешние пакеты в `build.py` и `tools/*` без
   очень веской причины: проект должен собираться на голом Python.
2. **`site/` — генерируемый каталог.** Он в `.gitignore`; не коммитьте его и не правьте руками.
3. **`docs/STATE.md` и `docs/MANIFEST.json` — генерируются** `build.py` (`tools/gen_state.py`).
   Правьте контент и код, а не эти файлы.
4. **Внутренние ссылки — только через схемы** `lesson:`, `page:`, `module:`.
   Валидатор ловит битые ссылки, но лучше не создавать их вовсе.
5. **Схемы — код.** Новая диаграмма = функция в `tools/gen_diagrams.py` + запись в `DIAGRAMS`.
   Файлы `assets/img/diagrams/*.svg` не хранятся в репозитории.
6. **CI зелёный или PR не готов.** `validate --strict`, `test_build.py`, `build.py` обязаны
   проходить: то же самое запускается в `.github/workflows/ci.yml`.
7. **Тон и точность контента.** Урока без практического примера и проверки понимания в курсе не бывает.

## 3. Что обновлять после каждого изменения

| Изменение | Обязательные шаги |
| --- | --- |
| Новый урок | `content/<модуль>/NN-slug.md` по `docs/CONTENT_GUIDE.md`, затем `build.py` + `validate.py --strict` |
| Новая диаграмма | функция в `tools/gen_diagrams.py`, запись в `DIAGRAMS`, ссылка из урока |
| Новая страница | `content/pages/<slug>.md` (front matter: title, summary, order, icon) |
| Новый модуль | запись в `content/modules.yml`, каталог `content/<dir>/` с уроками и `index.md` |
| Сборка, шаблоны, стили | правка `build.py` / `tools/*` / `assets/*` + тест в `tools/test_build.py` |
| Изменение workflow | синхронно обновить уроки модуля 5 (там разбираются те же файлы) и `docs/ARCHITECTURE.md` |
| Любое изменение | запись в `docs/CHANGELOG.md` (дата, что, зачем) |

## 4. Формат записи в журнал изменений

```markdown
## [1.1.0] — 2026-10-20
### Добавлено
- Модуль 8, урок 5: «Симулятор команд» (`lesson:simulyator`).
### Изменено
- `tools/validate.py`: проверка якорей внутри страниц.
### Исправлено
- Битая ссылка на схему в уроке про rebase.
```

Версия курса живёт в `site.yml` (`version:`). Поднимайте MINOR при новых уроках и модулях,
PATCH — при исправлениях текста и кода.

## 5. Коммиты и Pull Request

- Сообщения в формате Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`.
- Один коммит — одна логическая правка; не смешивайте форматирование и содержимое.
- В PR заполняйте шаблон: что сделано, зачем, как проверено.
- Вливайте через squash и не переиспользуйте ветку после слияния.
- Не пушите в `main` напрямую и не делайте `--force` в общие ветки.

## 6. Проверка перед завершением работы

```text
[ ] python3 build.py                      — сборка проходит без предупреждений
[ ] python3 tools/validate.py --site site --strict   — контент и ссылки в порядке
[ ] python3 tools/test_build.py           — тесты зелёные
[ ] docs/CHANGELOG.md обновлён
[ ] версия в site.yml поднята, если есть пользовательские изменения
[ ] ссылки lesson:/page:/module: проверены валидатором
[ ] новые диаграммы зарегистрированы в DIAGRAMS
[ ] прогон CI на ветке зелёный (Actions → CI)
```

## 7. Как агент должен строить план работы

1. Прочитать `docs/STATE.md` (состав курса, инварианты, «что улучшить дальше»).
2. Прочитать `docs/CHANGELOG.md` (что уже сделано в последних итерациях).
3. Выбрать задачу и записать её в план как измеримый результат:
   «добавить урок X в модуль Y, обновить ссылки, прогнать проверки».
4. Работать маленькими шагами: правка → сборка → проверка.
5. Перед завершением пройти чек-лист из раздела 6 и оставить запись в журнале.

## 8. Если что-то сломалось

| Симптом | Что смотреть |
| --- | --- |
| `validate` ругается на ссылку | проверить slug и существование цели (`lesson:`, `page:`, `module:`) |
| Не сходится блок `:::` | закрывающая строка ровно `:::` без текста, вложенность не поддерживается |
| Схема не найдена | имя файла должно быть в `DIAGRAMS` (`tools/gen_diagrams.py`) |
| Тест падает на подсветке/шаблонах | смотреть `tools/test_build.py`: там описаны контракты |
| Workflow падает на Pages | включить Pages: Settings → Pages → Source: GitHub Actions |
| Прогон CI падает в шаге сборки | воспроизвести локально: `python3 build.py` |
